## 1. 项目概述

### 1.1 背景

Illusion 游戏（Koikatsu 等）拥有庞大的 Mod 社区，用户常常需要安装数十乃至数百个 `.zipmod` 文件。原生游戏不提供 Mod 管理功能，只能手动操作，极易产生：

- 不知道装了哪些 Mod、版本是什么
- 重复安装同一个 Mod 的不同版本，导致覆盖混乱
- 删除 Mod 困难，残留文件到处都是

### 1.2 目标

构建一款桌面端 Mod 管理工具，核心能力：

| 能力 | 说明 |
|------|------|
| **元数据解析** | 解析 `manifest.xml`，提取 guid / name / version / author |
| **重复检测** | 安装前校验 guid，阻止重复安装同一 Mod |
| **安装/卸载** | 解压 `.zipmod` 到游戏目录，卸载时精准清除 |
| **冲突检测** | 识别文件路径冲突，提示用户处理 |
| **启用/禁用** | 无需卸载，通过文件移出机制临时禁用 |
| **列表管理** | 查看已安装 Mod 的名称、版本、状态等信息 |

### 1.3 范围

- **支持游戏**：单款游戏（项目初期面向 Koikatsu/KK 系列，后续可扩展）
- **Mod 格式**：Sideloader `.zipmod` 格式（内含 `manifest.xml`）
- **支持平台**：Windows 10/11（64 位）
- **运行方式**：本地桌面应用，无需联网

## 2. Mod 格式分析

### 2.1 zipmod 文件结构

`.zipmod` 本质上是一个标准 ZIP 压缩包，扩展名不同。其内部结构如下：

```
[Makise]GS-Alice.zipmod
├── manifest.xml                           ← 必须存在，包含 Mod 元数据
├── abdata/
│   ├── chara/
│   │   └── [Makise]GS-Alice.unity3d      ← 角色资源
│   │   └── thumb/
│   │       └── [Makise]GS-Alice.png      ← 缩略图
│   └── list/
│       └── characustom/
│           ├── [Makise]GS-Alice_hair.csv
│           ├── [Makise]GS-Alice_top.csv
│           └── ...                        ← 服装/配件列表数据
```

### 2.2 manifest.xml 格式

```xml
<manifest schema-ver="1">
  <guid>[Makise]GS-Alice</guid>        <!-- 全局唯一标识符，重复检测的核心字段 -->
  <name>[Makise]GS-Alice</name>        <!-- 显示名称 -->
  <version>1</version>                 <!-- 版本号（字符串，如 "1"、"2.0"、"1.0.0"） -->
  <author>Makise</author>              <!-- 作者 -->
  <description> </description>        <!-- 描述（可为空） -->
  <website> </website>                 <!-- 作者网站（可为空） -->
</manifest>
```

### 2.3 关键字段说明

| 字段 | 类型 | 必须 | 说明 |
|------|------|------|------|
| `guid` | string | ✅ | Mod 全局唯一标识，**重复检测的核心依据** |
| `name` | string | ✅ | Mod 显示名称 |
| `version` | string | ✅ | 版本号，格式不固定（"1"、"2.0"、"1.0.0" 均有） |
| `author` | string | ⚠ 建议 | 作者名 |
| `description` | string | ❌ | 描述，常为空 |
| `website` | string | ❌ | 作者主页/来源链接 |

> **重要**：`guid` 是 Sideloader 用于唯一标识 Mod 的字段，同一个 Mod 的不同版本 guid 相同。因此可以用 `guid` 来检测重复安装，并在升级时识别"新版本替换旧版本"的场景。

### 2.4 文件放置目标目录

`.zipmod` 内的文件路径即为相对于游戏根目录的安装路径，无需做任何路径转换：

```
压缩包内路径：  abdata/chara/[Makise]GS-Alice.unity3d
安装到游戏：    {游戏根目录}/abdata/chara/[Makise]GS-Alice.unity3d
```

Sideloader 加载的 Mod 文件统一放在游戏根目录的 `mods/` 子目录中（保留 `.zipmod` 格式），而**不是**直接解压到游戏目录。但本工具选择**解压安装**方式，与 Sideloader 直接读取 zipmod 的方式不同，需注意：

> **架构决策**：本工具采用"解压安装"方案（而非 Sideloader 的 zipmod 直接读取方案），优点是安装后无需依赖 Sideloader 运行时，缺点是禁用/卸载需要自行管理文件。

## 3. 需求分析

### 3.1 用户故事

```
作为玩家，我想要：
  1. 拖拽一个 .zipmod 文件到工具上，自动安装到游戏目录
  2. 安装时自动读取 manifest.xml，显示 Mod 的名称、作者、版本
  3. 安装时检测是否已有相同 guid 的 Mod，阻止重复安装并提示
  4. 若检测到相同 guid 但版本不同，提示是否升级
  5. 看到已安装的所有 Mod 列表，包括名称、版本、状态
  6. 一键禁用某个 Mod 而不删除它，之后可重新启用
  7. 卸载一个 Mod 时，工具能精准删除它的所有文件
```

### 3.2 功能需求

#### 必须实现（MVP）

- [ ] **F01** 游戏路径配置：设置游戏根目录路径
- [ ] **F02** manifest.xml 解析：安装前读取并校验元数据
- [ ] **F03** 重复安装检测：按 `guid` 阻止重复安装，提示已安装版本
- [ ] **F04** Mod 安装：解压 `.zipmod` 并复制文件到游戏目录
- [ ] **F05** Mod 列表展示：列表显示已安装 Mod 的元数据信息
- [ ] **F06** Mod 卸载：根据文件记录精确删除 Mod 文件

#### 应该实现（v1.0）

- [ ] **F07** 版本升级提示：guid 相同但版本不同时提示"是否升级"
- [ ] **F08** Mod 启用/禁用：将 Mod 文件移入/移出隔离区实现软切换
- [ ] **F09** 冲突检测：安装前检查是否有文件路径冲突
- [ ] **F10** 安装历史记录：记录安装、卸载、启用、禁用操作日志

#### 可以实现（v2.0+）

- [ ] **F11** 搜索与筛选：按名称、作者、版本、状态过滤 Mod 列表
- [ ] **F12** 缩略图显示：从 `.zipmod` 中提取 `thumb/*.png` 展示预览图
- [ ] **F13** 导出 Mod 清单：导出已安装 Mod 列表为 JSON/CSV

### 3.3 非功能需求

| 类型 | 要求 |
|------|------|
| 性能 | 扫描 500 个 Mod 的列表加载 < 3 秒 |
| 安全 | 操作文件前验证游戏路径合法，防止路径穿越 |
| 健壮 | manifest.xml 缺失或格式异常时给出明确错误提示，不崩溃 |

## 6. 核心模块设计

### 6.1 `manifest_service` ★ — 元数据解析与校验（新增核心模块）

这是新增的核心模块，负责读取并校验 `manifest.xml`，同时承担**重复安装检测**职责。

#### 6.1.1 数据类定义

```python
# app/services/manifest_service.py

from dataclasses import dataclass
from pathlib import Path
import zipfile
import xml.etree.ElementTree as ET


@dataclass
class ModManifest:
    """从 manifest.xml 解析出的 Mod 元数据"""
    guid: str           # 全局唯一标识符（重复检测依据）
    name: str           # Mod 显示名称
    version: str        # 版本号字符串
    author: str         # 作者
    description: str    # 描述（可为空）
    website: str        # 网站（可为空）

    def __str__(self) -> str:
        return f"{self.name} v{self.version} by {self.author} [{self.guid}]"
```

#### 6.1.2 解析逻辑

```python
class ManifestParseError(Exception):
    """manifest.xml 解析失败时抛出"""
    pass


class ManifestService:
    
    MANIFEST_FILENAME = "manifest.xml"

    def parse_from_zipmod(self, zipmod_path: Path) -> ModManifest:
        """
        从 .zipmod 文件中读取并解析 manifest.xml。
        
        Raises:
            ManifestParseError: manifest.xml 不存在、格式错误或缺少必要字段
        """
        if not zipfile.is_zipfile(zipmod_path):
            raise ManifestParseError(f"不是有效的 ZIP/zipmod 文件：{zipmod_path.name}")
        
        with zipfile.ZipFile(zipmod_path, "r") as zf:
            if self.MANIFEST_FILENAME not in zf.namelist():
                raise ManifestParseError(
                    f"压缩包中未找到 manifest.xml，请确认这是有效的 Sideloader zipmod 文件"
                )
            with zf.open(self.MANIFEST_FILENAME) as f:
                raw = f.read().decode("utf-8-sig")  # 处理 BOM（部分作者保存时带 BOM）
        
        return self._parse_xml(raw, zipmod_path.name)

    def _parse_xml(self, xml_content: str, source_name: str) -> ModManifest:
        """解析 XML 字符串，返回 ModManifest"""
        try:
            root = ET.fromstring(xml_content)
        except ET.ParseError as e:
            raise ManifestParseError(f"manifest.xml 格式错误：{e}（来源：{source_name}）")
        
        def get_text(tag: str, required: bool = True) -> str:
            elem = root.find(tag)
            if elem is None or (elem.text is None):
                if required:
                    raise ManifestParseError(
                        f"manifest.xml 缺少必要字段 <{tag}>（来源：{source_name}）"
                    )
                return ""
            return elem.text.strip()
        
        guid = get_text("guid", required=True)
        name = get_text("name", required=True)
        version = get_text("version", required=True)
        
        if not guid:
            raise ManifestParseError(f"manifest.xml 中 <guid> 不能为空（来源：{source_name}）")
        
        return ModManifest(
            guid=guid,
            name=name,
            version=version,
            author=get_text("author", required=False),
            description=get_text("description", required=False),
            website=get_text("website", required=False),
        )
```

#### 6.1.3 重复检测逻辑

```python
from enum import Enum

class DuplicateCheckResult(Enum):
    NO_DUPLICATE = "no_duplicate"       # 未发现重复，可正常安装
    SAME_VERSION = "same_version"       # 已安装相同 guid + 相同版本，阻止重复安装
    NEWER_VERSION = "newer_version"     # 新 Mod 版本 > 已装版本，提示"升级"
    OLDER_VERSION = "older_version"     # 新 Mod 版本 < 已装版本，提示"降级（谨慎）"

@dataclass
class DuplicateCheckReport:
    result: DuplicateCheckResult
    existing_mod_id: int | None = None      # 已安装 Mod 的数据库 ID
    existing_mod_name: str | None = None    # 已安装 Mod 的名称
    existing_version: str | None = None     # 已安装版本号
    incoming_version: str | None = None     # 待安装版本号


class ManifestService:
    # ... （接上方代码）

    def check_duplicate(
        self,
        manifest: ModManifest,
        db_session,  # SQLAlchemy Session
    ) -> DuplicateCheckReport:
        """
        根据 guid 检测重复安装。
        查询数据库中是否已有相同 guid 的 Mod 记录。
        """
        from app.models.mod import Mod
        
        existing: Mod | None = (
            db_session.query(Mod)
            .filter(Mod.guid == manifest.guid)
            .first()
        )
        
        if existing is None:
            return DuplicateCheckReport(result=DuplicateCheckResult.NO_DUPLICATE)
        
        # 版本比较（简单字符串比较，可升级为 packaging.version 语义化版本比较）
        if existing.version == manifest.version:
            result = DuplicateCheckResult.SAME_VERSION
        else:
            # 尝试语义化版本比较
            result = self._compare_versions(manifest.version, existing.version)
        
        return DuplicateCheckReport(
            result=result,
            existing_mod_id=existing.id,
            existing_mod_name=existing.name,
            existing_version=existing.version,
            incoming_version=manifest.version,
        )

    @staticmethod
    def _compare_versions(incoming: str, existing: str) -> DuplicateCheckResult:
        """
        简单版本比较。
        优先尝试语义化比较（1.0.0 > 0.9.0）；
        若格式不规范则回退到字符串比较。
        """
        try:
            from packaging.version import Version
            if Version(incoming) > Version(existing):
                return DuplicateCheckResult.NEWER_VERSION
            else:
                return DuplicateCheckResult.OLDER_VERSION
        except Exception:
            # 版本格式无法解析时，仅标记为"已存在，版本不同"
            return DuplicateCheckResult.NEWER_VERSION  # 保守处理，给用户选择权
```

### 6.2 `archive_service` — zipmod 文件处理

负责列出压缩包内文件和执行解压操作。

```python
# app/services/archive_service.py

import zipfile
from dataclasses import dataclass
from pathlib import Path


@dataclass
class ArchiveEntry:
    """压缩包内的单个文件条目"""
    archive_path: str   # 压缩包内路径，如 "abdata/chara/xxx.unity3d"
    size: int
    is_dir: bool = False


class ArchiveService:
    
    # manifest.xml 和其他工具性文件，安装时跳过（不解压到游戏目录）
    SKIP_FILES = {"manifest.xml", "manifest.xml/"}

    def list_entries(self, zipmod_path: Path) -> list[ArchiveEntry]:
        """
        列出 zipmod 内所有文件（不解压），过滤掉 manifest.xml 和目录条目。
        返回的路径即为相对游戏根目录的安装路径。
        """
        entries = []
        with zipfile.ZipFile(zipmod_path, "r") as zf:
            for info in zf.infolist():
                if info.filename in self.SKIP_FILES:
                    continue
                is_dir = info.filename.endswith("/")
                entries.append(ArchiveEntry(
                    archive_path=info.filename,
                    size=info.file_size,
                    is_dir=is_dir,
                ))
        return entries

    def extract_to(
        self,
        zipmod_path: Path,
        game_root: Path,
        files_to_extract: list[str] | None = None,
    ) -> list[str]:
        """
        解压 zipmod 到游戏根目录。
        
        Args:
            zipmod_path: .zipmod 文件路径
            game_root: 游戏根目录（解压目标）
            files_to_extract: 若指定，则只解压这些文件（选择性安装用）
        
        Returns:
            实际写入的文件相对路径列表（相对游戏根目录）
        
        Note:
            manifest.xml 始终跳过，不会写入游戏目录。
        """
        written: list[str] = []
        with zipfile.ZipFile(zipmod_path, "r") as zf:
            for info in zf.infolist():
                rel_path = info.filename
                
                # 跳过不需要的文件
                if rel_path in self.SKIP_FILES or rel_path.endswith("/"):
                    continue
                if files_to_extract is not None and rel_path not in files_to_extract:
                    continue
                
                # 安全性检查：防止路径穿越
                dest = safe_extract_path(game_root, rel_path)
                dest.parent.mkdir(parents=True, exist_ok=True)
                
                with zf.open(info) as src, open(dest, "wb") as dst:
                    dst.write(src.read())
                
                written.append(rel_path)
        
        return written


def safe_extract_path(game_root: Path, relative: str) -> Path:
    """路径安全校验，防止路径穿越攻击"""
    resolved = (game_root / relative).resolve()
    if not str(resolved).startswith(str(game_root.resolve())):
        raise ValueError(f"路径穿越检测：{relative}")
    return resolved
```

### 6.3 `conflict_service` — 文件冲突检测

```python
# app/services/conflict_service.py

from dataclasses import dataclass, field


@dataclass
class ConflictItem:
    relative_path: str       # 冲突的文件路径
    existing_mod_id: int
    existing_mod_name: str


@dataclass
class ConflictReport:
    conflicts: list[ConflictItem] = field(default_factory=list)
    
    @property
    def has_conflicts(self) -> bool:
        return bool(self.conflicts)


class ConflictService:
    
    def check(
        self,
        incoming_files: list[str],  # 待安装 Mod 的文件路径列表
        db_session,
    ) -> ConflictReport:
        """
        与数据库中 mod_files 表比对，找出路径冲突。
        """
        from app.models.mod import ModFile, Mod
        
        conflicts = []
        for rel_path in incoming_files:
            existing_file = (
                db_session.query(ModFile)
                .filter(ModFile.relative_path == rel_path)
                .join(Mod)
                .first()
            )
            if existing_file:
                conflicts.append(ConflictItem(
                    relative_path=rel_path,
                    existing_mod_id=existing_file.mod.id,
                    existing_mod_name=existing_file.mod.name,
                ))
        
        return ConflictReport(conflicts=conflicts)
```

### 6.4 `mod_service` — Mod 核心业务

```python
# app/services/mod_service.py

from pathlib import Path
from dataclasses import dataclass, field
from app.services.manifest_service import ManifestService, DuplicateCheckResult
from app.services.archive_service import ArchiveService
from app.services.conflict_service import ConflictService, ConflictReport
from app.models.mod import Mod, ModFile, ModStatus


@dataclass
class InstallOptions:
    overwrite_conflicts: bool = False       # 是否强制覆盖文件冲突
    files_to_install: list[str] | None = None  # 选择性安装（None = 全部）
    allow_upgrade: bool = False             # 是否允许升级（替换旧版本）
    allow_downgrade: bool = False           # 是否允许降级


@dataclass
class InstallPreview:
    """安装前预检结果，用于 UI 展示"""
    manifest: "ModManifest"                         # 解析出的元数据
    files: list[str]                                # 待安装文件列表
    duplicate_report: "DuplicateCheckReport"        # 重复检测结果
    conflict_report: ConflictReport                 # 文件冲突检测结果
    
    @property
    def can_install_directly(self) -> bool:
        """无需用户确认可直接安装"""
        return (
            self.duplicate_report.result == DuplicateCheckResult.NO_DUPLICATE
            and not self.conflict_report.has_conflicts
        )


class ModService:

    def __init__(self, game_root: Path, db_session):
        self.game_root = game_root
        self.session = db_session
        self.manifest_svc = ManifestService()
        self.archive_svc = ArchiveService()
        self.conflict_svc = ConflictService()

    # ──────────────────────────────────────────────
    # 安装预检（返回预检结果，不执行实际安装）
    # ──────────────────────────────────────────────

    def preview_install(self, zipmod_path: Path) -> InstallPreview:
        """
        安装前预检，不执行任何文件写入操作。
        UI 层调用此方法，根据返回结果决定是否弹对话框。
        
        流程：
          1. 解析 manifest.xml，获取元数据
          2. 重复检测（guid 查重）
          3. 获取文件列表（过滤 manifest.xml）
          4. 文件冲突检测
          5. 返回 InstallPreview
        """
        # 步骤 1：解析 manifest.xml
        manifest = self.manifest_svc.parse_from_zipmod(zipmod_path)
        
        # 步骤 2：重复检测
        dup_report = self.manifest_svc.check_duplicate(manifest, self.session)
        
        # 步骤 3：获取文件列表
        entries = self.archive_svc.list_entries(zipmod_path)
        files = [e.archive_path for e in entries if not e.is_dir]
        
        # 步骤 4：文件冲突检测
        conflict_report = self.conflict_svc.check(files, self.session)
        
        return InstallPreview(
            manifest=manifest,
            files=files,
            duplicate_report=dup_report,
            conflict_report=conflict_report,
        )

    # ──────────────────────────────────────────────
    # 执行安装
    # ──────────────────────────────────────────────

    def install(
        self,
        zipmod_path: Path,
        preview: InstallPreview,
        options: InstallOptions,
    ) -> Mod:
        """
        执行实际安装。调用前应先调用 preview_install 并由用户确认。
        
        重复处理策略：
          - SAME_VERSION：直接拒绝，抛出异常
          - NEWER_VERSION + allow_upgrade=True：先卸载旧版本，再安装新版本
          - OLDER_VERSION + allow_downgrade=True：同上（降级）
        """
        dup = preview.duplicate_report
        
        # 处理重复安装
        if dup.result == DuplicateCheckResult.SAME_VERSION:
            raise ValueError(
                f"已安装相同版本的 Mod（guid: {preview.manifest.guid}，"
                f"版本: {dup.existing_version}），请勿重复安装"
            )
        
        if dup.result in (DuplicateCheckResult.NEWER_VERSION, DuplicateCheckResult.OLDER_VERSION):
            if not options.allow_upgrade and dup.result == DuplicateCheckResult.NEWER_VERSION:
                raise ValueError("检测到旧版本，需要用户确认是否升级")
            if not options.allow_downgrade and dup.result == DuplicateCheckResult.OLDER_VERSION:
                raise ValueError("检测到更新版本，需要用户确认是否降级")
            # 先卸载旧版本
            self.uninstall(dup.existing_mod_id)
        
        # 执行解压
        files_written = self.archive_svc.extract_to(
            zipmod_path,
            self.game_root,
            files_to_extract=options.files_to_install,
        )
        
        # 写入数据库
        mod = Mod(
            guid=preview.manifest.guid,
            name=preview.manifest.name,
            version=preview.manifest.version,
            author=preview.manifest.author,
            description=preview.manifest.description,
            website=preview.manifest.website,
            archive_name=zipmod_path.name,
            status=ModStatus.ENABLED,
        )
        self.session.add(mod)
        self.session.flush()  # 获取 mod.id
        
        for rel_path in files_written:
            self.session.add(ModFile(mod_id=mod.id, relative_path=rel_path))
        
        self.session.commit()
        return mod

    # ──────────────────────────────────────────────
    # 卸载
    # ──────────────────────────────────────────────

    def uninstall(self, mod_id: int) -> None:
        """
        精确卸载：根据数据库文件记录逐一删除文件，然后清理空目录。
        """
        mod: Mod = self.session.get(Mod, mod_id)
        if mod is None:
            raise ValueError(f"Mod ID {mod_id} 不存在")
        
        for mod_file in mod.files:
            # 考虑文件可能已被禁用（在隔离区）
            file_path = self._get_actual_path(mod, mod_file.relative_path)
            if file_path.exists():
                file_path.unlink()
        
        # 清理空目录（可选）
        self._cleanup_empty_dirs()
        
        self.session.delete(mod)
        self.session.commit()

    # ──────────────────────────────────────────────
    # 启用 / 禁用
    # ──────────────────────────────────────────────

    def disable(self, mod_id: int) -> None:
        """将 Mod 文件移动到隔离区 {game_root}/.kkmm/disabled/{mod_id}/"""
        mod: Mod = self.session.get(Mod, mod_id)
        isolation_root = self.game_root / ".kkmm" / "disabled" / str(mod_id)
        
        for mod_file in mod.files:
            src = self.game_root / mod_file.relative_path
            dst = isolation_root / mod_file.relative_path
            dst.parent.mkdir(parents=True, exist_ok=True)
            if src.exists():
                src.rename(dst)
        
        mod.status = ModStatus.DISABLED
        self.session.commit()

    def enable(self, mod_id: int) -> None:
        """将 Mod 文件从隔离区移回游戏目录"""
        mod: Mod = self.session.get(Mod, mod_id)
        isolation_root = self.game_root / ".kkmm" / "disabled" / str(mod_id)
        
        for mod_file in mod.files:
            src = isolation_root / mod_file.relative_path
            dst = self.game_root / mod_file.relative_path
            dst.parent.mkdir(parents=True, exist_ok=True)
            if src.exists():
                src.rename(dst)
        
        mod.status = ModStatus.ENABLED
        self.session.commit()

    # ──────────────────────────────────────────────
    # 内部工具方法
    # ──────────────────────────────────────────────

    def _get_actual_path(self, mod: "Mod", relative_path: str) -> Path:
        """根据 Mod 状态返回文件实际所在路径（游戏目录或隔离区）"""
        if mod.status == ModStatus.DISABLED:
            return self.game_root / ".kkmm" / "disabled" / str(mod.id) / relative_path
        return self.game_root / relative_path

    def _cleanup_empty_dirs(self) -> None:
        """清理游戏目录中的空目录（从深到浅）"""
        import os
        for dirpath, dirnames, filenames in os.walk(
            self.game_root, topdown=False
        ):
            path = Path(dirpath)
            # 不清理游戏根目录本身和 .kkmm 隔离区
            if path == self.game_root or ".kkmm" in path.parts:
                continue
            try:
                path.rmdir()  # 仅在目录为空时成功
            except OSError:
                pass
```

### 7.1 数据库表结构（SQLAlchemy ORM）

#### `mods` 表（含 manifest 元数据字段）

```python
# app/models/mod.py

from enum import Enum as PyEnum
from sqlalchemy import String, Enum, DateTime
from sqlalchemy.orm import Mapped, mapped_column, relationship
from app.database import Base
from datetime import datetime

class ModStatus(PyEnum):
    ENABLED = "enabled"
    DISABLED = "disabled"

class Mod(Base):
    __tablename__ = "mods"
    
    id: Mapped[int] = mapped_column(primary_key=True)
    
    # ── manifest.xml 字段 ──────────────────────────────
    guid: Mapped[str] = mapped_column(String(200), nullable=False, unique=True, index=True)
    # guid 加唯一索引，是重复检测的数据库级保障
    name: Mapped[str] = mapped_column(String(200), nullable=False)
    version: Mapped[str] = mapped_column(String(50), nullable=False)
    author: Mapped[str] = mapped_column(String(100), default="")
    description: Mapped[str] = mapped_column(String(1000), default="")
    website: Mapped[str] = mapped_column(String(500), default="")
    # ──────────────────────────────────────────────────
    
    archive_name: Mapped[str] = mapped_column(String(200))    # 原始文件名，如 "[Makise]GS-Alice.zipmod"
    status: Mapped[ModStatus] = mapped_column(Enum(ModStatus), default=ModStatus.ENABLED)
    notes: Mapped[str] = mapped_column(String(1000), default="")        # 用户备注
    installed_at: Mapped[datetime] = mapped_column(DateTime, default=datetime.now)
    
    files: Mapped[list["ModFile"]] = relationship(
        back_populates="mod",
        cascade="all, delete-orphan",
    )

    # —— 仓库mod相对路径（仅 REPO 记录使用，GAME 记录始终为 ""）——
    repo_relative_path: Mapped[str] = mapped_column(String(1000), default="", comment="仓库mod的相对路径")


class ModFile(Base):
    __tablename__ = "mod_files"
    
    id: Mapped[int] = mapped_column(primary_key=True)
    mod_id: Mapped[int] = mapped_column(
        ForeignKey("mods.id"), nullable=False, index=True
    )
    relative_path: Mapped[str] = mapped_column(String(500), nullable=False, index=True)
    # 如 "abdata/chara/[Makise]GS-Alice.unity3d"
    
    mod: Mapped["Mod"] = relationship(back_populates="files")
```

> **设计要点**：`guid` 字段设置了 `unique=True` 约束，这是数据库层面的"防止重复安装"最后一道保障。即使业务层逻辑出现 Bug，数据库也会拒绝插入 guid 重复的记录。

**REPO 端文件路径解析**：`resolve_repo_mod_path(mod, repo_root)` 优先使用 `mod.repo_relative_path` 拼出绝对路径；`repo_relative_path` 为空时回退到 `get_author_dir(repo_root, mod.author) / mod.current_file_name`（兼容老数据）。GAME 端文件路径维持 `get_author_dir(game_mod_path, mod.author) / mod.current_file_name`，不依赖 `repo_relative_path`。

## 12. 已知问题与注意事项

### 12.1 manifest.xml 健壮性

- **BOM 头**：部分创作者使用 UTF-8 with BOM 保存 manifest.xml，解析时需用 `"utf-8-sig"` 解码（已在代码中处理）
- **空白字段**：`description`、`website` 常为空白字符串或只有空格，需 `.strip()` 处理
- **`guid` 特殊字符**：guid 可能包含方括号、空格（如 `[Makise]GS-Alice`），数据库存储和查询时无需特殊处理，但 UI 显示时需注意
- **缺少 manifest.xml 的 Mod**：极少数旧版 Mod 无 manifest.xml，应明确提示用户"此文件不是有效的 zipmod"

### 12.2 版本号比较

- Illusion Mod 的版本号格式不统一：有的是 `"1"`，有的是 `"2.0"`，有的是 `"1.0.0"`，甚至有 `"v1.2"` 带前缀 v
- 优先使用 `packaging.version.Version` 进行语义化比较；若解析失败则回退为字符串比较，并标注"版本格式无法解析"

### 12.3 guid 唯一性说明

- guid 由 Mod 作者自行定义，社区中绝大多数都遵循唯一性约定
- 极少数非官方重打包的 Mod 可能 guid 相同但内容不同，这是上游问题，工具无法自动处理
- 数据库 `guid UNIQUE` 约束在这种情况下会阻止安装，需提示用户手动处理

### 12.4 文件系统注意事项

- **路径安全性**：已在 `safe_extract_path` 中处理路径穿越检测
- **文件占用**：游戏运行时可能占用 `.unity3d` 等文件，操作前建议提示用户关闭游戏
- **长路径（Windows）**：游戏路径较深时可能触发 260 字符限制，必要时在注册表开启长路径支持
